# 用户身份验证插件

通过 QQ 号精确认证配置中的特殊用户，并把可信身份及分阶段关系便签发送给 MaiBot 的 Planner 和 Replyer。

v2.3.0 面向 MaiBot 1.3.4+ / maibot_sdk 2.x，使用官方 Hook，不修改 MaiBot 主程序，不读取人物画像作为身份依据。

## 功能

- 只使用平台提供的 QQ 号认证身份，昵称、群名片和消息正文不能创建身份。
- 使用 `(session_id, message_id)` 精确绑定发送者，不再用群聊最近发言者兜底。
- Planner 每条消息只添加 `verified_identity` 临时属性；关系背景在动态尾部按身份说明一次，不在每条历史消息里重复。
- 原生对象列表直接添加、删除和排序用户，保存后热更新，无需重载插件。
- 每个特殊用户分别配置 Planner 规划便签和 Replyer 回复便签。
- 任一便签留空时，该阶段只接收可信身份，即 Identity Only。
- 同一 QQ 可以同时配置全局身份和群专属身份，群专属配置优先。
- 未配置或未命中的普通用户不会收到任何身份或安全提醒 Prompt。
- 人物画像仍由 MaiBot 自行注入，只作为背景参考，不参与本插件认证。

## 安装

1. 将插件目录放入 MaiBot 的 `plugins/`。
2. 重启 MaiBot 或重载插件。
3. 在 WebUI 插件配置的「用户」区块添加项目，填写 QQ、关系称呼和两张便签，然后保存。
4. 使用 `/owner_auth_status` 查看索引和注入状态。

未配置有效 QQ 时，插件保持静默。

## 配置

### 通用设置

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| 启用插件 | 关闭后不再传递身份或关系便签 | 开 |
| 私聊中注入 | 是否在私聊中认证特殊用户 | 开 |
| 同时注入行动规划 | 是否向 Planner 传递身份与规划便签 | 开 |
| 插件记录注入日志 | 记录身份命中和失败关闭 | 开 |
| 日志显示等级 | `INFO` / `DEBUG` / `WARNING` | INFO |
| 身份索引会话有效期 | 清理不活跃会话索引；活跃会话中的单条消息不按 TTL 中途掉标 | 300 秒 |

### 用户列表

列表长度就是用户数量，不再单独设置数量。通用设置和用户列表在同一页显示。在「用户」区块点击「添加项目」创建用户，拖动调整顺序，点击删除按钮移除条目；这些操作在当前页面即时显示，保存后才应用到插件。默认列表为空。

删除表示移除身份配置；临时停用请关闭该条目的「启用此用户」。同一 QQ 的群专属配置优先；同一范围重复配置时取列表中第一个。

原生对象列表使用单行输入框编辑便签。未编辑的多行内容会完整保留；需要编辑多行时，使用同一配置页的源码模式。列表标题、字段标签和占位提示均由插件提供，不需要修改 Dashboard。

### 每个用户

| 字段 | 说明 |
| --- | --- |
| 启用此用户 | 临时停用该用户，不清空配置 |
| 用户 QQ 号 | 唯一身份凭据 |
| 关系称呼 | 例如「主人」或「老师」 |
| 限制群聊 | 留空表示全局，填写群号表示仅在该群生效 |
| Planner 规划便签 | 只影响行动规划；留空表示 Planner Identity Only |
| Replyer 回复便签 | 只影响最终措辞；留空表示 Replyer Identity Only |

两个便签都支持以下标准占位符：

| 占位符 | 含义 |
| --- | --- |
| `{relation}` | 当前身份的关系称呼，例如“主人” |
| `{display_name}` | 已清洗的聊天显示名 |
| `{user_id}` | 已认证的平台账号 ID |
| `{message}` | 已清洗并截断的目标消息文本 |
| `{relations}` | 所有启用身份的关系称呼 |

旧版 Prompt 使用的 `{nickname}`、`{owner_nickname}`、`{qq}`、`{owner_qq}`、`{user_qq}`、`{msg}`、`{user}` 和 `{owner_names}` 仍作为兼容别名保留，但新配置不建议继续使用 `owner_*` 命名。

配置值只做单遍占位符替换，不会二次展开。

## 注入流程

```text
入站消息
  -> chat.receive.after_process
  -> 保存 (session_id, message_id) 对应的 QQ 发送者快照

Planner 请求
  -> maisaka.planner.before_request
  -> 按上下文中的 msg_id 精确查快照
  -> 在本次消息副本增加 verified_identity
  -> 在动态尾部添加一次身份映射与非空 Planner 规划便签

Replyer 请求
  -> maisaka.replyer.before_request
  -> 按 reply_message_id 精确查目标发送者
  -> 在最终 user 动态尾部添加身份凭证和非空 Replyer 回复便签
```

任何精确定位失败都会跳过注入。插件不会把同一会话的最近发言者当作当前回复对象。

## Prompt Cache

- Planner 的身份字段协议固定追加在 system 尾部，每轮内容一致。
- 配置不变时，同一历史消息的身份属性由不可变消息号决定，连续请求保持一致；列表顺序或身份配置改变后按当前 QQ 和群范围重新认证。
- 每用户身份映射与规划便签放在 MaiBot 已有当前时间等动态内容之后；空便签仍保留身份映射，不附加行为要求。
- Replyer 身份和回复便签使用最终 `extra_prompt`，不动态修改 system。凭证只核验回复对象，关系作为背景，不规定回复称呼。
- Planner 在缓存未命中时按真实会话和消息号补查当前请求中的历史消息，最多并发 4 次；重载或淘汰后仍可恢复身份，不依赖昵称或最近发言者。首次恢复可能改变历史前缀，后续请求保持一致。消息未入库或查询失败时不猜测身份。

## 人物画像

MaiBot 会按 `platform + user_id` 选择相关人物画像并作为 Planner 内部参考。画像查询可能超时、为空或只包含部分背景，而且不会直接注入 Replyer。因此本插件不把人物画像当作认证结果：

```text
身份插件：确定“这个账号是谁”以及对该身份使用哪张关系便签
人物画像：补充兴趣、经历、近期互动等背景
```

画像中的昵称或关系描述不能创建、覆盖 `verified_identity`。

## 固定槽位配置迁移

当前 2.2.2 配置会在加载时按编号顺序转换为用户列表，保留 QQ、群范围、启用状态和两张便签，包括明确留空的便签。仅迁移原 `user_count` 范围内的槽位，避免启用原本未生效的用户。

插件版本为 2.3.0；配置兼容版本 `plugin.config_version` 保留 2.2.2。宿主在配置版本升级时会先裁剪新模型未知字段，保留兼容版本才能让插件从原始数据中迁移 `userN`。请勿手动将配置兼容版本改成插件版本。

迁移只处理内存数据，不在配置回调里读写文件。首次可视化保存会写入用户列表；原生保存可能保留旧的 `userN` 节，但只要存在 `users` 列表节，旧槽位就不再参与认证，包括列表为空的情况。删除后保存不会恢复旧用户。

0.x／2.1 配置请先升级到 2.2.2 并完成旧配置迁移，再升级到此版本，不支持跳过中间版本直接升级。

## 排障

`/owner_auth_status` 会显示：

- 用户列表条目数量和已配置 QQ 数量；
- 当前用户是否命中；
- 消息身份索引条数和会话数；
- Planner 累计身份标注；
- Replyer 累计精确认证；
- 身份定位失败关闭次数；
- 最近一次注入阶段和脱敏 QQ。

将日志等级设为 `DEBUG` 可查看实际注入文本。日志中的 QQ 默认脱敏。

## 兼容性

- MaiBot：`1.3.4` 到 `1.99.x`（当前钩子使用 Context Items；已在 1.3.8 验证）
- maibot_sdk：`2.0.0` 到 `2.99.x`
- Python：跟随 MaiBot 运行环境
- 第三方依赖：无
